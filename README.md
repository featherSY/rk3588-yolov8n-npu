# RK3588 YOLOv8n NPU 部署

RK3588 NPU 上的 YOLOv8n INT8 混合量化部署与板级系统认知。

> 文档中的 IP 与路径为作者实机环境值，复现时请替换为自己的板端地址与路径。

## 核心结果

精度结论基于 **全量 COCO val2017（5000 张）**，详见[最终评测报告 §2.1](docs/RK3588-YOLOv8n-NPU-最终评测报告.md)。

| 方案                                    |     模型体积 | mAP@0.5 | mAP@0.5:0.95 |        相对 FP32 掉点 |
| ------------------------------------- | -------: | ------: | -----------: | ----------------: |
| x86 ORT FP32 基线                       | 12.85 MB |  0.4987 |       0.3552 |                 — |
| RK3588 INT8 主干 + FP16 `model.22` head |  5.67 MB |  0.4889 |       0.3426 | −0.0098 / −0.0125 |

默认部署方案为 INT8 主干 + FP16 检测头：全量下掉点 **0.98 / 1.25 点**，满足 <2 点目标；板端内部速度基准 33.30 ms / 30.0 FPS。

> 报告 §2 的 8 方案横向筛选表使用按文件名排序的前 500 张子集，仅为过程记录；该子集绝对 mAP 偏高，不与上表混用。

## 性能口径

- `33.30 ms / 30.0 FPS` 是单图重复、仅计 `rknn.inference()` 的板端内部基准。
- `35.82 ms / 39.44 ms` 是图片序列流式纯前向 / 端到端；跨端对比只使用这一组。
- x86 同口径为 `37.89 / 42.20 ms`，环境为 ORT 1.26.0、`threads=0`、WSL 6 核。
- 历史 `26.5 / 27.0 / 31.0 ms` 已作废，不用于任何结论或加速比计算。
- 板端无图像输入设备，输入为 COCO val2017 图片序列；本项目不宣称“摄像头实时采集”或“实时 30 FPS”。
- 三核 `--core 012` 只是默认核配置，实测对单帧小模型无加速，不作为性能亮点。
- 精度评测集为全量 val2017（5000 张），两端使用同一份官方标注。

## 目录导览

- `docs/`：先读最终评测报告，再读板级系统与驱动认知笔记。前者给出精度、速度、误差定位和复现命令；后者解释 BSP、驱动形态、设备节点与调频机制。
- `scripts/convert/`：WSL 侧 ONNX 拆分、混合量化、转换和 RKNN 诊断脚本。
- `scripts/board/`：板端图片推理、图片序列流式演示、输出诊断、BSP 探查和 NPU 核配置测试。
- `scripts/eval/`：mAP 评估、结果比较和跨端同口径性能对齐。
- `scripts/env/`：板端目录与依赖准备脚本。
- `legacy/x86-stage/`：第一阶段 x86 基线、ONNX 检查、早期量化和线程实验脚本，仅供追溯。

## 复现入口

完整命令见[最终评测报告的“复现命令”章节](docs/RK3588-YOLOv8n-NPU-最终评测报告.md#7-复现命令全部真实路径可直接复制)，§7.2 为全量 5000 张复评流程。

转换与 ORT 评估在 WSL 运行；板端推理通过 `scp` 传送模型和结果。WSL 与板端的 `results/` 各自管理本端产物，不要混用相对路径。

## 环境依赖

- `rknn-toolkit2`：2.3.2
- `rknn-toolkit-lite2`：2.3.2
- RKNN driver：0.9.8
- ONNX Runtime：1.26.0

约 66 MB 的 RKNN 二进制依赖包、模型和运行产物不纳入仓库，请按上述版本自行安装或由转换流程重新生成。
